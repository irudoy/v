# Exact proof reuse and group preparation

`kb proof-group` reads one saved coherent function description and an exact
prepared-original manifest. It reports reusable source components, incompatible
operands and missing obligations. The default preparation path reads source
text and saved artifacts. Canonical facts, reviews and receipts retain their
existing guarded publication lifecycle.

```sh
uv run kb proof-group tmp/groups.json --function 7mfk:0005525a \
  --prepared tmp/prepared-originals.json --json
```

Saved inputs belong under `tmp/` or `.kb/` in the current checkout. The response
binds their complete bytes and checks them again after the read. Duplicate JSON
keys refuse the input. The existing saved group format retains each exact
original canonical claim and its SHA, subject, function and source candidates.
`--requirements tmp/requirements.json` supplies a JSON object keyed by original
SHA with explicit `sites`, `width`, `entry`, `phase`, `premises`, `call_premises`,
`image` and `analysis` values. It cannot replace the original datum, function or
direction. A missing requirement remains unknown and uncovered.

## Existing source owners

The index reads the normal ordinary-family registry and its validated reference
descriptors. Calculation dispositions retain their existing separate registry,
and coherent-copy members retain their existing lane/transfer tuples and caller
parents. Each reference retains exact original SHA, datum, ordered sites,
physical width/direction, function, known entry/phase and declared premises.
Native types and full preimage/postimage identities stay separate from physical
transfer width. Missing entry, phase or call facts are not inferred from shared
function membership.

Prepared subtraction requires a current exact reference with the declared
source, component, identity and call binding. Saved older group status fields do
not determine that subtraction. Unknown/stale prepared references stay explicit
in `prepared_manifest_unresolved`. Source preparation is distinct from accepted
execution. By default accepted status is `not-evaluated`.

`--accepted` asks the existing guarded ordinary-family consumer for an exact
original's current accepted scope. It cannot transfer acceptance from another
original, an incompatible datum or a different function. The response keeps the
existing exact-original status separate from requested structural compatibility.
This option retains the existing consumers' required verification work,
including instruction or numerical checks where that consumer requires them.
The report itself never admits requested coverage, units, scale, native geometry,
reverse identity or hardware behavior. Calculation and coherent status without
that normal guarded query remains unevaluated.

## Exact comparison and flow structure

Each candidate lists covered metadata obligations, unknown required bindings and
explicit incompatibilities. Original identity, datum, ordered site list, width,
direction, function, entry, phase, input premises, actual call premises, image
and analysis binding are compared independently. Width types are exact; Boolean
and integer values are distinct. A known empty concrete call list is separate
from unknown call premises.

`--flow tmp/flow.json` adds one saved `kb flow` response; the option is repeatable.
The supported component, datum/load/width, source definitions, result carriers,
ordered definition edges, image, descriptor, input, source and L0 bindings must
match the current source. Stale or contradictory structure remains unresolved.
Only structural entry/call/analysis bindings are supplied. The independent
instruction-state, numerical, physical, branch/call/return, fixed-other causal,
native/types/TEST/scopes and same-primary obligations retain their consumers.

Sharing absolute helper `00022590` supplies no proof that `FFFF2C1C` feeds that
call. The learning boundary reads `FFFF134E` or `FFFF1350` before the real
`00057D86` call. A different datum retains an explicit mismatch even when its
callee matches. No result is supplied for an unsupported or ambiguous edge.

## Declared source closure

`proof_sources.py` reads source text through Python AST and C/assembly includes;
it imports or executes none of the discovered modules. Explicit declarations,
local imports, numerical helper imports and finite loader targets extend the
source seeds. Existing registry/projection targets and the complete primary's
private SH tool source boundary supply finite loader declarations. Unknown
dynamic loaders, conflicting local imports, missing declared files and missing
persistent includes remain unresolved.

Capture-owned generated input headers have a separate role from persistent
source includes. Their bytes remain bound by the actual producer and independent
consumer; the file inventory does not require a private runtime header in the
checkout. Other missing includes refuse the closure. The closure includes the
root build/dependency declarations and workspace package declaration. It makes
no minimality claim for shared imported tool code.

`--inputs tmp/source-checkpoint.json` uses a saved complete source checkpoint or
original producer input map. Without that option, the normal current execution
input builder supplies the map. Missing/stale source bindings and missing
acceptance anchors remain obligations. Both numerical source files of the
coolant reference must reach the complete map even when a helper is imported
through another numerical file.

The pipeline acceptance group derives its complete declared adapter dependencies
from this same source graph. Both reference domain consumers require that graph
in their actual execution inputs before domain admission. Source consistency,
closure and refusal tests belong to the complete shared acceptance. Static
discovery and a compatible source report supply no executable qualification.
