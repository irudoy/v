# Bounded proof adapters

The `[adapter]` table of an existing bounded stock descriptor owns its standard
input mapping and raw observation transport. `proof_adapter.py` renders the
input-only header, C driver and structural refusal sources for that declaration.
`proof_transport.py` independently decodes the actual stdout schema. Neither
module establishes a firmware result or grants semantic evidence.

The `ordinary-80-572` profile uses the existing complete observer: an 80-byte
incoming context, a 572-byte result, both 192-byte frame images, complete CPU and
external ABI state, and both 64 KiB ordinary RAM images. Ordered calibration
spans remain complete before and after the invocation. A descriptor can also
require ordered complete code/pool spans. The observer assembly and original
instruction fixtures remain sources of their existing domain contracts.

## Declaration

The schema requires the output names, exact entries and kind discriminator,
ordered typed scalar fields, aligned RAM assignments, calibration spans,
optional bound-byte spans and exact source dependencies. Each RAM assignment
names one input field or one explicit constant. Multiple assignments to the
same byte, out-of-range fields, result-bearing field names, undeclared paths
and unsupported observer profiles refuse generation. The domain contract pins
the complete reviewed adapter declaration in addition to its original stock,
alias, boundary and admission checks.

`calibration_input = true` serializes complete controlled calibration bytes
from the domain's input callback. The generated driver writes only those spans.
With `false`, the driver only observes the declared fixture data. Case selection,
context construction and calibration extraction remain domain input operations.
The generator selects only declared inputs; it does not copy expected outputs,
terminal registers or numerical results from a legacy fixture.

The coolant descriptor combines byte and word RAM inputs with controlled ROM
operands and complete code/pool observation. The MAF record descriptor uses
constant sibling bytes, a selected record member, separate helper and caller
entries, an explicit argument/GBR premise and read-only fixture literals. Both
use the same driver/header renderer and complete raw decoder.

The remaining RPM descriptor uses three separate caller entries, controlled
calibrations and complete code/pool/outside-return observation. Its constant
quiet diagnostic status and bounded diagnostic count retain a domain-owned
premise. It uses the same transport while preserving separate scalar, physical,
natural-call, return and actual caller-result obligations.

The CVTC descriptor uses natural state/duty roots, a fixed incoming bank2
index, complete ordinary RAM and controlled byte/word calibration inputs.
Natural RTS paths and the real curve, quotient and remainder helpers remain
unchanged. The same renderer and decoder transport inputs and observations;
independent transition/product/duty equations, physical calls/returns and
fixed-other actual-output alternatives retain separate admission.

## Source generation and acceptance

Run `python3 tools/sh-elf-run/generate_proof_adapters.py --write` to write only
the declared C drivers and structural refusal test sources. It does not load a
ROM, construct a domain matrix, call a numerical model, execute instructions,
prepare a native publication or publish a receipt. The private input header is
rendered from explicit input cases during the existing capture lifecycle.

`make check` invokes the generator with `--check`. The producer and independent
consumer also reject a stale generated driver or refusal source. Generated
sources, generator, decoder, declared dependencies and structural refusal helper
belong to the complete execution inputs and acceptance anchors. The normal
shared TEST/GNU lifecycle supplies executable acceptance.

The declared dependency graph in [`proof-reuse.md`](proof-reuse.md) includes
imported numerical helpers. Both reference domain consumers require its complete
current execution-input bindings before domain admission. The pipeline source
gate also derives those dependencies and retains private generated headers as
runtime inputs with independently checked bytes.

Common structural refusals cover incomplete/duplicate transport, altered entry
or phase, missing RAM/context/frame/result/calibration bytes, duplicate JSON
keys, substituted decoded rows and missing or duplicate terminal markers.
Domain-specific instruction-state, numerical, physical-site, natural-call,
post-delay, branch, return and fixed-other causal checks remain independent and
mandatory. Exact native preimages/postimages, semantic types, TEST origins and
positions, scopes, same-primary binding and guarded publication retain their
existing consumers. Sharing transport establishes none of those claims and
supplies no scale or reverse identity evidence.

Source-prepared adapters retain a distinct status from accepted execution.
Source size and generated lines describe maintenance responsibilities; they do
not establish elapsed-time improvement or firmware coverage.
