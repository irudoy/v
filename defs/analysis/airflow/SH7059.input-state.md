# SH7059 input and engine-state paths

The stock 1ME3B and 1EK7A ROMs publish coolant and intake-air temperature
through independently bound acquisition and conversion functions. The
[sensor acquisition](SH7059.sensor-acquisition.md) describes the capture
registers and the multiplexed ADC entry points.

| Value or stage | 1ME3B | 1EK7A |
| --- | --- | --- |
| Coolant ADC sample | `0xFFFE8D18` | `0xFFFE8D2C` |
| Coolant conversion and fallback task | `0x00043304` | `0x000442FC` |
| Published coolant byte | `0xFFFE8079` | `0xFFFE809D` |
| IAT ADC sample | `0xFFFE8D0C` | `0xFFFE8D20` |
| IAT filter | `0x0004A07C` | `0x0004B3F4` |
| Filtered IAT ADC coordinate | `0xFFFE9924` | `0xFFFE996E` |
| IAT conversion and fallback task | `0x0004A0E2` | `0x0004B45A` |
| Published IAT byte | `0xFFFE9928` | `0xFFFE9972` |

The ADC scan reads and right-aligns ADDR0 for the coolant sample. The
coolant producer reads that sample, applies range and fallback selection,
and writes the published byte. The IAT filter copies the first sample and
uses `(3 * previous + sample) >> 2` on subsequent update passes, with a
one-count increment if truncation would otherwise leave a rising value
unchanged. The conversion uses an 8-bit curve or the fixed `0x4B`
fallback, then sets its publication flag.

## Dual-bank MAF acquisition and publication

The airflow ADC task requests selectors `0x03` and `0x0F` from the
paired sampler. The sampler uses `0xFFFFF800 + 2 * 0x03` for ADDR3
and `0xFFFFF820 + 2 * (0x0F - 0x0C)` for ADDR15. It returns ADDR15
at caller `SP+4` and ADDR3 at `SP+8`.
The caller shifts each result right by six. The bank-1 publisher reads
the ADDR15 result and the periodic airflow task reads ADDR3 for bank 2.

| Operation | 1ME3B | 1EK7A |
| --- | --- | --- |
| Paired sampler call and entry | `0x0002ED4E` calls `0x00035F5C` | `0x0002FA6A` calls `0x00036E28` |
| Read ADDR3 and ADDR15 in the sampler | `0x00036046`, `0x0003604C` | `0x00036F12`, `0x00036F18` |
| Store bank-1 ADC word | `0x0002ED68` to `0xFFFE8D1A` | `0x0002FA84` to `0xFFFE8D2E` |
| Store bank-2 ADC word | `0x0002ED6A` to `0xFFFE8D1C` | `0x0002FA86` to `0xFFFE8D30` |
| Call bank-1 publisher with channel zero | `0x00048CCC` calls `0x00048D66` | `0x00049FFC` calls `0x0004A096` |
| Check the gain and restore unity if required | `0x0009A058`, gain at `0xFFFEC0F0` | `0x0009DD14`, gain at `0xFFFEC588` |
| Q15 multiplication helper | `0x0009A0A0` | `0x0009DD60` |
| Publish bank-1 voltage word | `0x00048DAA` to `0xFFFE8024` | `0x0004A0DA` to `0xFFFE8028` |
| Publish bank-2 voltage word | `0x00048D10` to `0xFFFE8026` | `0x0004A040` to `0xFFFE802A` |
| Scheduler copies the voltage words for B1 and B2 | `0x000212B2` to `0xFFFE8018`, `0x000212B8` to `0xFFFE801A` | `0x000212E8` to `0xFFFE801A`, `0x000212EC` to `0xFFFE801C` |

For both channels the helper returns
`min(65535, (uint16(sample) * uint16(gain)) >> 15)`. The publisher
adds one to that halfword when the original sample equals `0x03FF`.
When its gate permits the range check, the gain validator replaces values
outside `0x7900..0x8700` with the ROM unity value `0x8000`. The range
check reads bit 0 at `0xFFFEBA6B` on 1ME3B and bit 4 at `0xFFFEBE10`
on 1EK7A. A set bit skips validation on the respective ROM.

These code paths establish the two ADC channel assignments and the firmware
voltage words. Physical connector terminals and the voltage scale at the
sensor remain subject to hardware evidence.

## Dual-bank MAF transfer curves

The airflow calculation prepares one input word per bank. With the
corresponding initialization bit clear it copies the published voltage
and sets the bit. Subsequent passes subtract the quotient calculated from
the previous conditioned word and the bank correction state, with a
floor of zero. 1ME3B calls a separate conditioner for bank 1 and inlines
bank 2. 1EK7A conditions both words in the main calculation.

| Operation | 1ME3B | 1EK7A |
| --- | --- | --- |
| Dual-bank calculation | `0x0004656A` | `0x00047816` |
| Prepare bank-1 voltage word | `0x00046DBE` writes `0xFFFE8DF0` | `0x00047888`, `0x00047890`, or `0x00047898` writes `0xFFFE8DEC` |
| Prepare bank-2 voltage word | `0x000465D6`, `0x000465DE`, or `0x000465E4` writes `0xFFFE8DF2` | `0x000478F8`, `0x00047900`, or `0x00047904` writes `0xFFFE8DEE` |
| Read bank-1 table argument | `0x000465EC` | `0x0004790C` |
| Call bank-1 transfer curve | `0x000465F6`, table `0x00015996` | `0x00047918`, table `0x000160D6` |
| Publish bank-1 curve output | `0x000465FE` to `0xFFFE804A` | `0x0004791C` to `0xFFFE806A` |
| Call bank-2 transfer curve | `0x00046608`, table `0x00015916` | `0x00047928`, table `0x00016056` |
| Publish bank-2 curve output | `0x00046614` to `0xFFFE804C` | `0x00047930` to `0xFFFE806C` |
| Read bank-1 curve output in downstream processing | `0x00046708` | `0x000479C8` |

The main calculation shifts each prepared word left by four and passes
the low halfword to the unsigned 64-cell interpolator. The retained
argument is therefore `(prepared_word & 0x0FFF) << 4`. The curve output
words carry the interpolation results before downstream conditioning
and per-bank contribution calculations. The periodic diagnostic publisher
scales the combined airflow-state word separately. It multiplies that word
by the ROM byte, shifts right by eight and saturates to a halfword.

| Total-airflow publication | 1ME3B | 1EK7A |
| --- | --- | --- |
| Airflow state and ROM multiplier | `0xFFFE804E`, `0x000083C1` | `0xFFFE8072`, `0x000083D9` |
| Result store | `0x00048D58` to `0xFFFEAE4E` | `0x0004A088` to `0xFFFEB186` |

The scheduler reads the bank-2 curve output with the adjacent halfword
as a longword at `0x0002129E` on 1ME3B and `0x00021324` on 1EK7A.
The curve function's own result store is a halfword on both ROMs.

## Normalized load publication

The live producer computes `min(255, floor(BFS * 128 / reference))`
from the unsigned base-fuel schedule (BFS) word. The stock reference
word is `0x9F38` on both ROMs. The scheduler copies the byte as the
most significant byte of a longword into the input snapshot.

| Operation | 1ME3B | 1EK7A |
| --- | --- | --- |
| Read the BFS word | `0x000484C4` from `0xFFFE802E` | `0x000497F4` from `0xFFFE8032` |
| Read the reference | `0x0004853C` from ROM `0x000094D4` | `0x0004986C` from ROM `0x00009626` |
| Store the live byte | `0x00048554` to `0xFFFE8048` | `0x00049884` to `0xFFFE8068` |
| Copy to the snapshot | `0x00021298` and `0x000212DA` to `0xFFFE8034` | `0x0002130C` and `0x00021326` to `0xFFFE8050` |
| Read and pass to knock lookup | `0x00071D86` and `0x00071D98` | `0x0007336A` and `0x0007337C` |
| Read and pass to ignition lookup | `0x000799EE` and `0x00079A02` | `0x0007B0D6` and `0x0007B0EA` |

The two-axis lookup consumers zero-extend the snapshot byte. An
additional 1EK7A path reads it at `0x00080154` and passes
`min(2 * snapshot, 255)` to the lookup at `0x00080166`.

## Engine speed publication

On 1ME3B the speed scaler at `0x000420C8` reads `0xFFFE8176` and
stores the live RPM coordinate at `0xFFFE81D6`. The scheduler copies the
containing longword from `0xFFFE81D4` to `0xFFFE819C`, placing its low
word at `0xFFFE819E`. On 1EK7A the corresponding scaler at `0x000430B8`
reads `0xFFFE819A` and writes `0xFFFE81FC`. The scheduler copies the
containing longword to `0xFFFE81C4`, placing the RPM coordinate in its
high word. Both scaler tasks derive the coordinate by shifting the
high-resolution input right by six.

## Vehicle speed publication

Both periodic HCAN1 receive dispatchers select the meter-frame decoder
for packed key `0x5000` (standard identifier `0x280`). The decoder
joins payload bytes 4 and 5 of software record 19 in big-endian order
and stores the unsigned quotient by ten. The speed write requires bit 3
of the first selector, value 1 in the second and zero in the third. Both
stock images carry `3B 01 00` at the selector locations.

| Stage | 1ME3B | 1EK7A |
| --- | --- | --- |
| HCAN1 receive dispatcher | `00120830` | `00140E94` |
| Key comparison, branch and decoder call | `00120944`, `00120948`, `00120B56` | `00140FA2`, `00140FA6`, `0014116E` |
| Meter-frame decoder | `00121FA2` | `00142606` |
| Stock receive selector bytes | `00008331`, `00008337`, `000088F6` | `00008341`, `00008347`, `00008960` |
| Receive-record bytes and load sites | `FFFEB1B3/FFFEB1B4` at `00121FC4/00121FCA` | `FFFEB4E9/FFFEB4EA` at `0014262E/00142634` |
| Publish CAN-derived word | `FFFE8120` at `00121FEA` | `FFFE8144` at `00142654` |
| Vehicle-speed update and source read | `00044756` reads at `000447CC` | `0004585E` reads at `000458D4` |
| Filter history and write sites | `FFFE8140` at `00044804/0004481A/00044848` | `FFFE8164` at `0004590C/00045922/00045958` |
| Live coarse byte and store | `FFFE816C` at `000448BC` | `FFFE8192` at `000459CE` |
| Additional published byte and word | `FFFE8028` at `000448B8`, `FFFE802A` at `000448A4` | `FFFE802C` at `000459CA`, `FFFE802E` at `000459B6` |
| Scheduler block-copy call and source/destination | `0002133A`, `FFFE8100 -> FFFE808C` | `00021386`, `FFFE8124 -> FFFE80B0` |
| Previous-cycle coarse byte | `FFFE80F8`, block offset `0x6C` | `FFFE811E`, block offset `0x6E` |

The filter uses `(15 * previous + input) >> 4`. Input below 20 clears
the filter, and the rising branch increments an unchanged truncated
result. The quantizer divides the filtered word by 20 and clips it to
255. The additional byte receives the same value as the live byte. The
word beside it holds `floor(filtered * 2 / 5)`.

The copy helpers transfer `0x74` bytes. A DFCO consumer reads the 1ME3B
snapshot at `000367AC`. The fuel-cut coordinator reads the 1EK7A snapshot
at `0007BF28`. Bus timing, physical speed accuracy, and the separate
word's physical scale require independent evidence.

## Throttle position acquisition

The 1ME3B and 1EK7A stock task tables contain consecutive entries for
the primary measurement and secondary conditioner. The primary
measurement selects mode 3 from the stock byte at the locations below.
Mode 3 enters the paired acquisition path. Further passes and learned-state
updates depend on runtime flags and comparisons.

| Stage | 1ME3B | 1EK7A |
| --- | --- | --- |
| Secondary ADC capture task | `0002EB72` | `0002F88E` |
| Bank-1 ADDR6 read and sample store | `0002ED6C`, `FFFEAC0A` at `0002ED7E` | `0002FA88`, `FFFEAF3A` at `0002FA9A` |
| Bank-2 ADDR18 read and sample store | `0002ED82`, `FFFEAC0C` at `0002ED92` | `0002FA9E`, `FFFEAF3C` at `0002FAAE` |
| Primary measurement pointer and entry | `00021F5C -> 0004B774` | `00021FE8 -> 0004CDBC` |
| Stock primary mode byte and instruction | `00008B69 = 03` at `0004B7BE` | `00008BE9 = 03` at `0004CE06` |
| Paired sampler call | `0004B802 -> 00035F5C` | `0004CE4A -> 00036E28` |
| Paired sampler load sites for selectors `0x07` and `0x13` | `00036046`, `0003604C` | `00036F12`, `00036F18` |
| Secondary conditioner pointer and entry | `00021F60 -> 0004B524` | `00021FEC -> 0004CB6C` |
| Snapshot copy | `00021448`, `FFFE980E -> FFFE96A8`, `0x166` bytes | `000214A6`, `FFFE9848 -> FFFE96D0`, `0x178` bytes |

The primary sampler takes ADC7 through selector `0x07` and returns
it through the R6 output pointer. Selector `0x13` supplies ADC19
through the R7 output pointer. The measurement right-aligns both
samples by six bits, accumulates each channel and publishes the
low halfwords. ADC19 supplies bank 1 and ADC7 supplies bank 2. The
secondary capture right-aligns ADC6 and ADC18 by six bits. The
conditioner publishes `0x0400 - sample` in unsigned halfwords and
stores its separately reference-corrected signed results alongside.
The corrected bank-2 results are at `0xFFFE994E` on 1ME3B and
`0xFFFE999A` on 1EK7A.

| Signal | 1ME3B live / snapshot / diagnostic read | 1EK7A live / snapshot / diagnostic read |
| --- | --- | --- |
| Bank 1 primary | `FFFE9948` at `0004B9AC` / `FFFE97E2` / `000FAC7E` | `FFFE9994` at `0004CFF4` / `FFFE981C` / `0010ED6A` |
| Bank 2 primary | `FFFE994A` at `0004B9A8` / `FFFE97E4` / `000FACFC` | `FFFE9996` at `0004CFF0` / `FFFE981E` / `0010EDEA` |

The P022x monitor reads the primary snapshots, and the P012x monitor
reads the secondary snapshots. The word in each row has a distinct
live address before the block copy. The KB telemetry names for bank 2
identify the live words. Connector terminals, physical
voltage calibration and observed scheduler cadence require separate evidence.

## Accelerator pedal

On 1ME3B and 1EK7A the scheduled pedal sampler calls the paired ADC helper
with selectors `0x0b` and `0x17`. The helper forms `fffff800 + 2 * 0x0b`
and `fffff820 + 2 * (0x17 - 12)`, waits for both conversions, and returns
ADDR11 and ADDR23 in that order. The sampler zero-extends and shifts each
result right by six before it stores the sampled words. The first channel
publisher copies its sample into the live diagnostic field. The second
channel publisher doubles its sample before storing the live diagnostic
field. The adjacent offset-corrected fields serve separate consumers.

| Stage | 1ME3B | 1EK7A |
| --- | --- | --- |
| Scheduler pointer and paired sample task | `00021f94`, `0002edd6` | `00022020`, `0002faf2` |
| Call to paired ADC helper | `0002ede4` calls `00035f5c` | `0002fb00` calls `00036e28` |
| ADC result loads in paired helper | `00036046`, `0003604c` | `00036f12`, `00036f18` |
| ADDR11 sample and store | `fffeabfc` at `0002ee00` | `fffeaf2c` at `0002fb1c` |
| ADDR23 sample and store | `fffeabfe` at `0002ee04` | `fffeaf2e` at `0002fb20` |
| Live APP1 and writer store | `fffe9834` at `000aaada` in `000aaac8` | `fffe9870` at `000aea06` in `000ae9f4` |
| Live APP2 and writer store | `fffe9838` at `000a3ef2` in `000a3edc` | `fffe9874` at `000a7a1e` in `000a7a08` |
| Scheduler copy call and block | `00021448`, `fffe980e` to `fffe96a8`, `0x166` bytes | `000214a6`, `fffe9848` to `fffe96d0`, `0x178` bytes |
| Published APP1 and range-monitor read | `fffe96ce` at `000fa662` | `fffe96f8` at `0010e73a` |
| Published APP2 and range-monitor read | `fffe96d2` at `000fa9dc` | `fffe96fc` at `0010eabe` |

The published words feed the APP1 P2122/P2123 and APP2 P2127/P2128 range
monitors. The APP offsets in the copy are `0x26` and `0x2a` for 1ME3B
and `0x28` and `0x2c` for 1EK7A.

On 1EK7A the stock dispatcher at `0x00020B14` invokes the APP1 and APP2
publishers through the consecutive table entries `0x00022094` and
`0x00022098`.

## Cruise steering switches

The ADC acquisition task copies ADDR14 (`fffff824`) into the steering
ladder input word after right-aligning the sample by six bits. The
configured decoder selects a window, records the corresponding one-hot
candidate, and accepts a repeated candidate. Its first accepted comparison
can initialize the previous candidate from the current pass. A separate
task shifts the five-byte history and stores the accepted code at its head.
The same scheduler block copy that publishes APP mirrors all five history
bytes. The ASCD control task publishes the stable code only when all five
snapshot samples agree.

| Stage | 1ME3B | 1EK7A |
| --- | --- | --- |
| ADDR14 load and ladder-input store | `0002ed96`, `0002eda8` to `fffeac00` | `0002fab2`, `0002fac4` to `fffeaf30` |
| Ladder decoder | `001386a4` | `00159f20` |
| Candidate and accepted code | `fffeacbc`, `fffeacba` | `fffeafee`, `fffeafec` |
| Accepted-code store | `001388da` | `0015a156` |
| History task, accepted-code read and head store | `0013767c`, `001378b4`, `001378b8` | `00158eec`, `0015913e`, `00159144` |
| Live history and snapshot history | `fffe98eb..fffe98ef`, `fffe9785..fffe9789` | `fffe992d..fffe9931`, `fffe97b5..fffe97b9` |
| Stable-code task and publication | `00134ec8`, `00135004` to `fffe9b8f` | `00155fc8`, `0015610c` to `fffe9c25` |

The stock 1ME3B configuration byte `0x3b` at `00008a62` enables the
ICC ladder path. The selector `0x0f` at `00008a6e` chooses its second
ladder. The auxiliary gate at `00008a74` has bit 0 clear. The stock
1EK7A main byte at `00008ad9` and auxiliary gate at `00008aec` are both
zero. The ADC still fills the ladder buffer, while the stock decode and
history gates prevent an active switch-code source from that input.

When the auxiliary gate is enabled, the decoder can compare the
right-aligned ADDR17 sample (`fffeac04` / `fffeaf34`) after a further
two-bit shift to set an auxiliary threshold flag. A separate gate-controlled
path in the history task also derives MAIN from bit 0 of `fffeba27` /
`fffebdca` and sets or clears the accepted code's MAIN state. Those
branches describe firmware configuration. Their upstream physical routing,
the switch terminals, and voltage response on the vehicle require
independent evidence.
