# Native diagnostic monitor paths on 1ME3B and 1EK7A

The stock monitoring routines report a local descriptor index to the DTC
reporter. The reporter and record marker form the common registration
path on 1ME3B and 1EK7A. The monitor inputs and report sites below
identify the per-layout registrations.

## Shared DTC path

| Role | 1ME3B | 1EK7A |
| --- | --- | --- |
| DTC reporter | `000c38f8` | `000c7990` |
| Dispatch to the runtime record marker | `000c3964` | `000c79fc` |
| Runtime record marker | `000d83ac` | `000deb60` |
| Stock descriptor table base | `0001bf58` | `0001c998` |
| Descriptor stride and flag selection | `000c3978..000c3988` | `000c7a10..000c7a1e` |

The report input is the record index in R4. The reporter delegates the
local index, and independently reads descriptor byte 8 at the original
index to select record-class handling. The first marker call retains
index 218 in stock. The tests at `000c3914` / `000c79ac` read `0x34` from
`0000888a` / `000088f6`, with bit 6 clear.

With that bit set and input index 218, the first marker call would select
49 on 1ME3B or 50 on 1EK7A if the corresponding P0455 status byte has
any bit of `0x60` set. Otherwise it would select 207 if that P0442 status
byte has any bit of `0x60` set, or 205 if both tests fail. The status byte
is byte 2 of the three-byte runtime record at base `fffed420` / `fffeda10`.
Local record-marker calls and descriptor-table reads are the machine
evidence for shared placement in `dtc_manager/block`.

## MAF circuit range

The circuit monitor consumes the scheduler's bank 1 and bank 2 MAF voltage
words. The primary low branch qualifies a voltage word below `0x0050`,
with an operating-state word at least `0x0020`. The primary high branch
qualifies a voltage word at or above `0x03d4`, with an unsigned state byte
at most `0xc0` and a further state byte equal to zero. These comparisons
use the same stock calibration values on both layouts. The voltage words
come from the [bank-specific scheduler copies](../airflow/SH7059.input-state.md).

record indices are 20, 66 through 71 and 130 through 132. Its 1EK7A indices

the coordinator reloads the circuit timers and skips the full report path.

## Throttle range

Each throttle range function receives a bank selector, with zero selecting
bank 1 and one selecting bank 2. The primary function reads the two primary
snapshots, and the secondary function reads the two secondary snapshots.
Both use the APP readiness gates above and the same unsigned range on their
own layout. A low input is below `0x003c` and a high input is above `0x03c4`.
Both thresholds are inclusive in the acceptable range. Each bank has its own
pending bit and delay byte. The first out-of-range pass sets pending and
loads 100. The full reporter requires a subsequent out-of-range pass with
pending set, delay zero and the direction's configuration bit set. An
in-range or unready pass clears pending and loads 100.

## Shared countdown service

The stock timer service decrements nonzero monitor delays and leaves zero
stable. The 8-bit group containing the APP, P2138 and TPS delays, the MAF
early-marker group, and the MAF 16-bit qualifying group execute in the

## MAF range/performance

The diagnostic tasks selected by `000222c8` (1ME3B) and `0002235c`
(1EK7A) call their respective MAF coordinators `000c96fc` and `000ce8ac`
at `000c007a` and `000c48be`. P0101 and P010B use separate range results
from the MAF circuit reports.

On 1ME3B, stock `ROM8[0001afe3] = 0x0f` enables the range branch when the
diagnostic readiness gates hold. The coordinator calls `000f2b54` at
`000c9a98` to qualify the high and low ratio decisions using the stock
timer thresholds of 1000, 50 and 500 enabled invocations. `000ca3b0`
requires the absolute difference between unsigned sensor words `fffe8018`
and `fffe801a` to exceed 60 raw counts. It produces report bits 3 and 2 in
`fffeb981`. The coordinator calls report index 177 (P0101) at `000c9c6e`
and index 7 (P010B) at `000c9c8e` when the respective bit is set.

On 1EK7A, the coordinator reaches `00105ab0` at `000ced2a`. The model
reads `ROM8[0001ba44]` at `00105b70`. Both tested configuration bits
are clear in stock, and `00105b8c` skips the ratio calculation, qualifier
`001060a0` and its timers. The result reader still tests existing state
bytes. P0101 (index 346) uses the runtime marker at `00106018` and the
full reporter at `0010604e`. P010B (index 347) uses those paths at
`00106008` and `00106028`. A separate state service receives the same
indices at `00105ff8` and `00105fe8`, respectively. The scheduled stock
model generates no new range result from cleared state.

The skipped qualifier uses scalar and curve bounds of zero and
`65535 / 256` in the stock calibration and 500 enabled invocations per
condition. The original attribute `0x0670` leaves bit 7 clear on these
descriptors, excluding them at the Mode 03 and Mode 07 attribute gate on SCI1 and CAN.

## Stock OBD response transmission on SCI1

On 1ME3B and 1EK7A, the Mode 03 and Mode 07 handlers tail-call a common
finalizer. It pads the response with zero DTC pairs up to three pairs,
sets the OBD session phase to 4, and clears bit 0 of the adjacent flags byte.
The dispatcher stages the response with header `48 6b 10`, service byte
`mode + 0x40`, and the payload. In phase 4, when the transmit gate byte
is zero, it reads the staged bytes in order, advances the cursor, and
accumulates their sum. Once the cursor reaches the response length, it sends
the low eight bits of the sum, clears the cursor and sum, and changes the
session phase.

| Session phase byte | `fffedfaa` | `fffee65a` |
| Dispatcher invocation in the serial service | `00036f6a` calls `0003e2c4` | `00037ee6` calls `0003f2ac` |

The traced path reaches the SCI1 registers on both layouts. The stock
cross-references at the buffer bases identify the dispatcher and the byte
append routine. The HCAN1 service has its own dispatch table, callbacks,
and response buffer as described below.

## Stock diagnostic reception on HCAN1

The application vector `RM1` (230) points to the HCAN1 diagnostic receive
handler. The controller uses physical mailboxes 27, 29 and 30 for these
requests. The mailbox initializer recognizes each of their ROM records as
receive type 2, selects MBC 2, and clears both local acceptance-mask words.
The three direct identifier stores then select the exact standard IDs.

| Physical mailbox | ROM record 1ME3B / 1EK7A | Direct ID store 1ME3B / 1EK7A | HCAN identifier word | Standard ID | RXPR1 bit |
| --- | --- | --- | --- | --- | --- |
| 27 | `00009834` / `000099AC` | `0011F206` / `0013F862` | `0x7DF0` | `0x7DF` | 11 |
| 29 | `0000983C` / `000099B4` | `0011F276` / `0013F8D2` | `0x7E00` | `0x7E0` | 13 |
| 30 | `00009840` / `000099B8` | `0011F2AA` / `0013F906` | `0x7D00` | `0x7D0` | 14 |

The zero masks require every standard ID bit to match. The physical
mailbox control field uses bits 14:4 for the standard ID. The generic
ROM mailbox records use a different encoding. Their packed IDs shift
right by one and are masked with `0x7FF0` before the register store.
The direct initialization above already uses the register format.
The SH7059/SH7058S hardware manual defines both the register and mask
fields in sections 17.3.2 and 17.3.4.

| --- | --- | --- |
| RM1 vector slot and entry | `0002039C` -> `001279C2` | `0002039C` -> `00148136` |
| Mailbox 30 call to functional ingress | `00127A42` calls `00127532` | `001481B6` calls `00147C7A` |
| Mailbox 29 call to physical ingress | `00127A9A` calls `00125E6E` | `0014820E` calls `001465C2` |

The interrupt checks RXPR1, copies eight hardware data bytes and
passes the mailbox DLC as a ninth software field. Mailboxes 27 and 30
use the functional single-frame ingress. That routine requires DLC 8,
a single-frame PCI length from 1 through 7, and its receive state to
be available. It removes the PCI byte, stages the PDU in channel 1
and marks it ready for the periodic diagnostic task.

Mailbox 29 uses the physical ISO-TP receiver. Its single-frame branch
also requires DLC 8, a PCI length from 1 through 7 and an available
receive state. It stages the PDU in channel 0 and calls the
receive-completion routine, which copies the staged length and marks
the channel ready. The periodic task consumes the ready indications
and calls the request dispatcher with the corresponding channel index.
The physical receiver also manages segmented reception. For channel 1 the
dispatcher reads the functional PDU at `0012676a` / `00146ebe` and writes
it into the shared buffer at `0012676e` / `00146ec2` when channel 0 is
available.

## CAN Mode 03 and Mode 07 application response

The stock application decoders at `0012665e` and `00146db2` use the first
request PDU byte to select a service. For Mode 03 and Mode 07, `SID & 0xc0`
is zero, so the decoder reads the low-group lookup table. The request bytes
`03` and `07` resolve to service indices `0x11` and `0x14`. The decoder
caches the index and copies it into bits 23:16 of the channel state before
testing the service's session mask.

| Item | 1ME3B | 1EK7A |
| --- | --- | --- |
| Channel-zero PDU buffer | `ffff06f8` | `ffff1c40` |
| Channel-zero PDU length word | `ffff0904` | `ffff1e4c` |
| Selected index byte | `ffff08f9` | `ffff1e41` |
| Channel-zero state word | `ffff08fc` | `ffff1e44` |
| Low-group lookup table | `00026f4c` | `000275b0` |
| Service table header and first record | `00026ce8`, `00026cf4` | `0002734c`, `00027358` |
| Mode 03 record and callback | `00026e8c`, `0012dbf8` | `000274f0`, `0014e598` |
| Mode 07 record and callback | `00026ed4`, `0012e5b0` | `00027538`, `0014f104` |
| Callback pointer load and call | `00126924`, `0012692c` | `00147078`, `00147080` |

The decoder uses a 24-byte record stride and loads the callback at
`first_record + 24 * index + 0x0c`. Both records have zero in their optional
pre-handler and completion fields at offsets `+0x08` and `+0x14`. The
halfword at `+0x04` is `0x0080` on 1ME3B and `0x0040` on 1EK7A. The decoder
requires the shifted session word and shifted record mask to share a set
bit. At the callback, `R4 = PDU + 1` and `R5 = (request_length - 1) &
0xffff`, with the subtraction result extended in the delay slot.

Both callbacks require a one-byte request SID. A nonzero argument length
stages response code `0x12`. Mode 07 also stages `0x12` when bit `0x02` in
ROM byte `00008a42` or `00008ab6` is clear. Both stock bytes are `0x2a`.

For a valid request, three RAM inhibit bits control whether each callback
scans the DTC list. On 1ME3B they are `fffeba15 & 0x80`, `fffeba32 & 0x01`,
and `fffeba65 & 0x02`. On 1EK7A they are `fffebdb8 & 0x80`, `fffebcf6 &
0x04`, and `fffebe09 & 0x01`. Any set inhibit bit leaves a positive body
with a zero count.

| Filter | Mode 03 | Mode 07 |
| --- | --- | --- |
| Byte 2 of the three-byte DTC runtime record | Mask `0x04` | Mask `0x08` |
| ROM descriptor attribute halfword, reached through the per-index pointer table | Mask `0x0080` | Mask `0x0080` |
| Additional per-group ROM enable test | | The computed mask intersects the group-enable byte |

The SCI1 and CAN Mode 03 and Mode 07 handlers read the same per-index ROM
attribute pointer table on each layout. On 1ME3B the SCI1 literals
`0003f4f0` / `00040570` and the CAN literals `0012dca8` / `0012e6d8`
all point to `0001cf00`. On 1EK7A the SCI1 literals `000404d8` / `00041558`
and the CAN literals `0014e64c` / `0014f230` all point to `0001da3c`.

Mode 07 takes the group index and mask selector from the first two bytes of
the 12-byte ROM record. A zero selector uses mask `1`, and a nonzero
selector uses the stock mask helper at `00022674` or `00022708`. The
group-enable bytes are indexed from `0001afb4` or `0001b9e0`. The third byte
of each DTC's RAM record and its separate ROM attribute halfword must also
pass the tests above.

Both callbacks serialize the low 16 bits of the second longword of each
selected ROM record in high-byte, low-byte order. The body starts with the
one-byte count followed by those code pairs. A completed positive body
length is `1 + 2 * count` bytes before its response SID is added.

## EVAP and rear O2 publication gates

For both ROMs, every reviewed EVAP and rear O2 descriptor in this section
has attribute `0x00a0`. This passes the `0x0080` attribute test shared by
SCI1 and CAN Mode 03 and Mode 07. Mode 03 also requires its runtime record
status. Mode 07 uses a separate group-enable test and runtime status mask.

Mode 07 takes the group index and mask selector from bytes 0 and 1 of the
record. The caller loads one into R0 at `0012e632` / `0014f186` and passes
the selector to `00022674` / `00022708`. The first eight offsets in its
jump table at `00022654` / `000226e8` are `0e 0c 0a 08 06 04 02 00`.

at `000226ac` / `00022740`. A zero selector also uses mask `0x01` directly.

## Stock diagnostic ISO-TP transmission on HCAN1

The stock CAN diagnostic task starts ISO-TP segmentation from the length in
the CAN response state. Its frame buffer has a separate address from the
SCI1 response buffer. The initial frame goes to HCAN1 physical mailbox 28.

| Stock location | 1ME3B | 1EK7A |
| --- | --- | --- |
| Single/first-frame segmenter | `00125d1c` | `00146470` |
| Diagnostic PDU byte-copy helper | `00126e8c` | `001475dc` |
| Eight-byte TX frame buffer | `ffff0924` | `ffff1e6c` |
| HCAN1 mailbox submitter | `001277f4` | `00147f68` |
| TXPR1 store | `001278d8` | `0014804c` |
| Periodic task tail branch and transport maintenance entry | `00126dda` -> `0012629c` | `0014752e` -> `001469f0` |

For lengths up to seven bytes, the segmenter writes the length as a
single-frame PCI byte and copies the PDU following it. For lengths of eight
bytes or more, it writes a first-frame PCI with `0x10` in the first byte's
high nibble, the length across its low nibble and the next byte, and six PDU
bytes. The copy helper uses the diagnostic PDU base from the table. Both
branches pass control to the same mailbox submitter after preparing the
eight-byte frame buffer.

The submitter writes `0x7e80` to `ffffdc80`, which encodes standard ID
`0x7e8` in bits 14:4 with IDE and RTR clear. It writes DLC 8, copies the
staged bytes to `ffffdc88..ffffdc8f`, and ORs `0x1000` into HCAN1 TXPR1 at `ffffd820`
when the controller-enable and mailbox-owner checks permit submission.
These are physical mailbox 28 and its request bit in the SH7059/SH7058S
hardware manual, table 17.2 and figure 17.3.

The application task releases its local stack frame before tail-branching
into transport maintenance. The maintenance routine services the transport
countdowns, advances the consecutive-frame sequence state, and calls the
same mailbox submitter when the pending transmit state allows it.
