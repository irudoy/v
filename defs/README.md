# defs - ECU table definition files

ROM table-definition files for the **VQ HR ECU** project; see `../AGENTS.md`.

- `reference/` contains local reference copies of public RomRaider
  Nissan/Infiniti definitions as Git submodules. This repository stores only the
  commit SHA pointer and `.gitmodules`; it does not republish their XML files.
  They are references for maps and table structure, **not** working definitions
  for this ROM. Their addresses belong to other ECUIDs and cannot be transferred
  directly.
- The project's working definition is built for the owned JK08A separately from
  `reference/`.

Neither repository includes a license file. Although published for community
use, they are legally unlicensed. A submodule stores only a SHA pointer to a
public commit, so this repository does not redistribute their unlicensed files.

As of July 2026, `Pytrex/NissanDefinitions` is the canonical Nissan RomRaider
collection, confirmed by the original definition author on the RomRaider forum.
The parser, checksum algorithms in `NissanChecksum.java`, and the HR `alt2` type
belong to `RomRaider/RomRaider` under GPL v2. It is not included as a submodule:
https://github.com/RomRaider/RomRaider.

## Working JK08A files

The canonical annotation layer for the owned target ROM `JK08A` lives directly
under `defs/`, separately from `reference/`:

- `JK08A.xml` is the RomRaider definition, projected from the graph, DTC
  registry, and presentation layer by `mapkit/emit_def.py`.
- `JK08A.xdf` is the TunerPro XDF 1.70 definition projected by the same
  generator from the same model. It contains the same emitted calibration
  tables, masked views, and two-state feature patches. It does not declare
  editor-side checksum processing.
- `JK08A.maps.csv` is the catalog ledger projected from the graph by
  `maps/build_tracker.py`. Its diagnostic columns contain reviewed static
  context and priority from the graph; they do not infer map identity from
  names.
- `JK08A.diagnostic-bindings.csv` is the reviewed per-ROM bridge from firmware
  `Func`, `Reg`, `Map`, and `Axis` nodes to diagnostic parameters, DTC codes,
  and CAN signals. Each row preserves firmware confidence, source
  applicability, inheritance scope, priority, and machine-address evidence as
  separate fields. Exact-ROM rows do not transfer to JK03A.
- `JK08A.dtc.csv` is an address registry for 36 analyzed DTC
  descriptor/attribute pairs. A descriptor is 12 bytes; the address of its
  associated `uint16` attribute comes from a pointer table. The generator
  validates both regions against the exact stock ROM. RomRaider receives one
  native `TableSwitch` per mutable range: `1/2 Descriptor` selects the stock
  12-byte descriptor or 12 zero bytes, and `2/2 Attribute` selects the stock
  two-byte attribute or its disabled value. Both controls must use the same
  state before saving. P1610 has a stock-zero attribute and therefore requires
  only its descriptor switch. TunerPro receives one atomic `XDFPATCH` per DTC
  and one atomic `XDFPATCH` per value of the `group` column. The seven group
  patches contain the same 71 mutable ranges as the 36 individual patches.
  There is no catch-all DTC patch.
- `JK08A.notes.md` is a handwritten reverse-engineering journal containing
  rationale, listings, and traces. It is not loaded into the graph.
- `JK08A.dfco.md` is the code-grounded subsystem model for deceleration fuel
  cut, including threshold selection, timers, the five-state machine, final
  six-channel arbitration, and the ATU-II injector-output path.
- `JK08A.fuel.md` is the code-grounded main-fuel model from dual-bank MAF and
  Base Fuel Schedule through Fuel Compensation Main, periodic multiplier,
  bank-specific trims, six compensated pulse words, and the explicitly bounded
  ATU-II hardware-output trace.
- `JK08A.fuel-inhibit.md` is the complete static model of all 15 global
  fuel-output inhibit contributors, the Power Balance replacement, the
  ETC-actuator-fault auxiliary mask, and final six-channel precedence.
- `JK08A.limiters.md` is the code-grounded arbitration model for the main and
  stationary engine-speed fuel cuts and the separate rotational-speed request
  limiter, including periodic execution order and exact fuel-mask precedence.
- The tracked common `JK08A.xml` and `JK08A.xdf` include the five-slot
  map-switching projection under the unchanged `JK08A` identity.
  `../patches/map-switching-layout.toml` owns the
  ten-family ROM/RAM layout and the exact CAN 0x551 feedback boundary,
  `../patches/map-switching-adapter-helper.s` and
  `../patches/map-switching-adapters.s` implement the Ghidra-assembled
  fail-closed accessors for the legacy adapter families,
  `../patches/map-switching-full-dfco-adapter.s` implements the shared
  four-family DFCO accessor,
  `../patches/map-switching-startup-wrapper.s` and
  `../patches/map-switching-limiter-commit.s` implement startup refresh and
  the SR-protected transaction for both direct limiter families,
  `../tools/mapkit/map_switching.py` projects 50 slot tables and ten
  slot-specific masked ignition views, and
  `../tools/mapkit/validate_map_switching.py` renders the projection against
  the live graph and verifies both tracked common definition files.
  The eight standalone assembly units pass 116 Ghidra p-code cases: 17 selector,
  76 adapter, 14 startup/limiter, and nine feedback cases.
  An independent machine-word audit covers all 414 instructions, including 39
  delayed transfers with encoded `NOP` slots, 52 PC-relative references, 77
  direct branch targets, and 21 indirect control transfers.
  `../tools/ghidra/EmulateMapSwitchingComposition.java` repeats all 116 cases
  over 5140 instructions from the complete locked fixture, reaches all eleven code
  entries at final addresses, and verifies the same SHA-256 and write boundary
  as `../patches/map_switching_compose.py`. Feedback uses state value `2` with
  locked `10, 10` on/off frame counts; the V36 meter response remains a hardware
  validation gate. `../patches/apply_map_switching.py` accepts a checksum-valid
  JK08A input with lower-partition calibration/configuration changes, requires
  exact protected code and patch anchors, initializes Map 2 through Map 5 from
  the input Map 1 values, injects the tracked SHA-locked payloads, recalculates
  all checksum domains, and writes a non-overwriting ROM plus MD5 sidecar.
  `../patches/upgrade_map_switching_reset.py` accepts only the complete pre-fix
  runtime with an exact protected upper partition outside declared
  map-switching and checksum storage,
  restores the stock fallback-clear anchor, installs the reset-fixed startup
  wrapper, recalculates checksums, and preserves calibration bytes.
  Map 1 uses canonical stock storage. Map 2 through Map 5 point to erased
  `0xFF` allocations in the stock image and become runtime-active only with
  the project patch. Their presence in the common definitions does not imply
  stock map-switching support. Each slot table remains in the canonical
  functional category and carries the slot number in its editor name. No
  separate map-switching definition identity exists.
- The handwritten calibration-layer sources are `JK08A.interp.csv` for
  interpolation-input geometry, `JK08A.findings.csv` for map findings,
  `JK08A.axes.csv` for axis semantics, and `JK08A.overrides.toml` for definition
  presentation. Its `[presentation]` policy and per-table `emit` fields select
  the tuner-facing subset without removing research maps from the graph or
  ledger. `JK08A.diagnostic-bindings.csv` supplies the reviewed diagnostic
  bridge. Their contract is `../tools/map-flag-pipeline.md`.
- Resolver reference censuses are
  `JK08A.map_inventory.{26944,26984,26b84}.csv` from `MapInventory` per kernel,
  and `JK08A.direct_lookup_inventory.csv` from `DirectLookupInventory` for the
  implicit-axis bank.
- `rom-inheritance.toml` explicitly binds exact-code ROMs to the canonical
  annotation set. It pins both image SHA-256 values and byte-verifiable
  executable-code ranges.

There is no live `JK03A.*` set under `defs/`. Donor `JK03A` retains its own image,
headless export, and Memgraph node layer, but receives structural and semantic
annotations from `JK08A` through `rom-inheritance.toml`. Before ingestion, the
loader verifies SHA-256 and equality of the declared code ranges, then measures
table ranges and hashes from each ROM's own image. A JK08A change therefore
reaches the JK03A layer on the next ingestion without synchronizing copies.
Historical A/B artifacts access old JK03A files only as commit-qualified Git
objects.

## Relevance of reference definitions

A definition is identified by `romid` fields such as ECUID, model, year, market,
and memory model, not by engine name.

**VQ35HR** (SH7058, 1 MB, dual CVTC without VVEL) is the project HR architecture
and the closest structural donor:

- `Pytrex-NissanDefinitions/Nissan Definitions/350Z/EV18A.xml`: ECUID `1EV18A`,
  USDM 2007 350Z HR, SH7058, **190 tables**. This is the deepest definition:
  fuel including base schedule, target AFR, injector latency/magnitude, MAF,
  LTFT/STFT, and per-cylinder trims; ignition including main, high-octane, and
  high-detonation 16x16 maps, cranking, and retard; **dual CVTC Intake, Exhaust,
  Cold, and High-Detonation Cam Timing Maps**; knock, torque, rev/speed limiters,
  idle, ETC flags, and `alt2` checksum.
- `.../G35/CF92A.xml`: ECUID `CF92A`, USDM 2007 Infiniti G35 **V36 sedan**,
  SH705823/SH7058, **146 tables**. It shares the V36 body platform with the test
  Skyline but uses VQ35HR rather than VQ25HR.
- `.../350Z/EV15A.xml` has 33 partial tables. `EV13B`, `EV16A`, and `EV19B` have
  no tables and only identify ROMs.
- `.../A2L.xml`, with about 330 tables, is the master template derived from a
  factory Nissan/Renault A2L. Together with `ScalingData.xml`, it is the table
  and scaling dictionary inherited by the other definitions.

**VQ37VHR** (SH7059, 1.5 MB, VVEL plus dual CVTC) is the MCU class of the JDM
`1ND0A` / `1ND3B` ROMs:

- `a33b-NissanDefs/1NX4A.xml`: ECUID `11NX4A`, 2011 Infiniti G37 S, SH7059,
  **30 tables** for fuel/ignition trims, MAF/MAF2, per-cylinder values, knock
  slice, fuel cut/restore, idle, ECT, and e-throttle/VVEL learning lattice. It
  lacks base cam-phasing and VVEL maps.
- `a33b-NissanDefs/6GE2C.xml`: ECUID `16GE2C`, 2017 370Z, SH7059, checksum only
  with `flashmethod=nis-can`.
- `a33b-NissanDefs/table_templates/` contains the NISSAN_BASE template.

**VQ25HR**, used by the JDM V36 Skyline 250GT, has no public definition. It is a
non-VVEL dual-CVTC member of the VQ35HR class. In the definition corpus, SH7059
appears only on VVEL VQ37VHR (`1NX4A`, `6GE2C`); all non-VVEL VQ definitions use
SH7058 or an older MCU. The structural donors are therefore `EV18A` and `CF92A`:
SH7058, Hitachi CAN, and dual CVTC.

Donor `JK03A` and owned target `JK08A` identify themselves as
**SH705822N (SH7058, 1 MiB)** and share software ID `7MFKAVN86`. Their
`0x020000..0x0fffff` regions are byte-identical, while configuration/calibration
differs at 121 byte positions. In the graph, only the measured values of four
currently unnamed candidate curves differ: `0x15360`, `0x15380`, `0x19090`, and
`0x190b0`. All 230 axes and the other 445 maps match.

Owned VQ35HR `JK00A` identifies itself as the same MCU class and software ID.
Its known executable ranges `0x000000..0x0081ff` and
`0x020000..0x0fffff` are byte-identical to JK03A and JK08A, while it differs
from them at 9,125 and 9,163 byte positions in configuration/calibration space.
This establishes a cross-application exact-code relationship, not map-value
equivalence. JK00A remains an inventoried binary without a Ghidra export,
Memgraph layer, or annotation inheritance entry.

The generated JK08A definitions contain a tuner-facing allowlist of 18
canonical maps and three masked ignition views. Map-switching projection provides
50 slot-specific calibration tables, for 58 calibration tables and 11 masked
views in the complete definitions.
Calibration axes are embedded in their tables; separate editable reference-axis
views are not emitted. The 432 other catalog maps, including internal
calculations, remain available in the graph, ledger, and presentation source.
All four code-proven DFCO RPM threshold tables are emitted. Reviewed static diagnostic context is included in map
comments and descriptions without changing map semantics or confidence.
`JK08A.xml` additionally contains 71 DTC switches and two verified native
RomRaider checksum handlers. Each ordinary DTC has adjacent descriptor and
attribute controls; P1610 has only its descriptor control. The checksum
handlers run in `alt` -> `alt2` order.

The working category tree follows the functional organization used by UpRev
and EcuTek:

- `Fuelling / Fuel Targets`, `Fuel Compensation`, `Overrun`, and `Engine Load`;
- `Ignition Timing / Main` and `Knock Control`;
- `Limiters / Rev Limit` and `Stationary Rev Limiter`;
- `Diagnostics / DTC` and `NATS / Immobilizer`.

Editor names omit addresses and use established vendor terminology where it
matches the recovered JK08A role. Addresses, confidence, and evidence remain in
the generated descriptions and canonical sources. `Fuel Targets` uses the
candidate gasoline-AFR projection `1881.6/x`: raw 128 is 14.70 AFR, raw 168 is
11.20 AFR, and raw 178 is 10.57 AFR. The code-proven centered raw arithmetic
remains separate in the map semantics and evidence.

`JK08A.xdf` contains 36 individual DTC patches and seven group patches:
`catalyst`, `evap`, `manufacturer_specific`, `misfire`, `nats`, `rear_o2`, and
`rear_o2_heater`. Individual and group patches overlap by design. Applying a
group makes all of its individual patches read as patched; changing only part
of a group makes the group state indeterminate. The patch payload remains
usable in that state, so scope selection must be deliberate. Each patch carries
stock `basedata` for every range.

Both definitions expose the Developer Immobilizer control at `0x8725`: `01`
applies the immobilizer normally and `00` enables immo-off. Engine starting and
operation were verified in the vehicle. TunerPro represents it as a reversible
one-entry patch. Its XDF intentionally has no checksum object because checksum
correction belongs to the flashing workflow. The three split-field ignition
maps use per-cell XDF conversion variables so editing the low seven bits
preserves bit 7, while editing the bit-7 view preserves the low seven bits.
Their low-seven-bit view is labeled `Timing adjustment (deg) [cand]`: it is a
relative trim of the calculated MBT value, not final ignition timing in BTDC.

The owned VQ35HR bench ROM `JK00D` independently confirms the
**SH705822N / SH7058 / 1 MiB** class.

The `flashmethod` attribute in HR definitions is unreliable metadata. SH7058
`EV18A`/`CF92A` and SH7059 `1NX4A` name `Nisprog`, but open-source
nisprog/npkern has no SH7059 flashing backend. These files are valuable for map
annotations, not for that tag.

## Initialization and updates

```bash
git submodule update --init defs/reference
# Move the pin to a newer upstream commit:
git -C defs/reference/Pytrex-NissanDefinitions fetch
git -C defs/reference/Pytrex-NissanDefinitions checkout <sha>
git add defs/reference/Pytrex-NissanDefinitions
```

## Known harmless artifact

On a case-insensitive filesystem such as macOS APFS or Windows, the
`a33b-NissanDefs` submodule reports `CD800.xml` or `cd800.xml` as modified. The
commit contains both paths and differs only by letter case, so such filesystems
map them to one file. This affects only submodule worktree status, not the pinned
SHA or HR definitions. Both files exist correctly on a case-sensitive
filesystem; no corrective edit is needed.
