# VQ37 VVEL nominal coolant-temperature axis

## Claim

`vvel_cold_axis/axis` is an eight-point big-endian `uint16` axis whose
runtime coordinate is an unsigned byte. Its stock points 20, 30, 40, 50,
60, 70, 80, and 90 display as -30..40 degC under the nominal `x-50`
encoding. `x+50` is the inverse of that coordinate grid, not an inverse
of the sensor, transfer lookup, conditioned publication, or snapshot chain.

The claim is a conditional nominal encoded-temperature interpretation at
level `code`. It does not establish measured coolant temperature, sensor
calibration, physical accuracy, or physical reachability of every breakpoint.
The stored axis width does not establish a physical `uint16` coordinate domain.

The executable contract is
`tools/mapkit/tests/test_vvel_cold_axis_scale.py#test_vvel_cold_axis_pid05_code_domain`.
Its independently retained fixture is
`tools/mapkit/tests/fixtures/vvel_cold_axis_pid05.json`. Each registered
JK78C, 1ND0A, 1ND3B, and 1ME3B image has its own full-image SHA binding and
reviewed instruction/data spans. Image identities and source paths belong to
`rom-images/roms.csv`; the fixture supplies independent expected bindings.
Shared-layout addresses do not substitute one image's execution for another's.

## Coordinate and PID relation

Let W be the incoming unsigned source word, q the stored sample byte, T the
unsigned result of the stock transfer lookup, P the conditioned publication,
x its coordinate snapshot, old the incoming previous publication, and A the
independently refreshed service-01/PID05 data byte.

```text
q = (W >> 2) & 255
T = stock_transfer_lookup(q)
A = max(T - 10, 0)
x = snapshot(P)

P = T       if T > old
P = old     if T <= old and T + 2 > old
P = T + 2   otherwise
```

The P relation applies to the normal source-validity branch q=3..241 with
the stock lookup-selection flag and without a service override. Overrides
supply P from a separate incoming byte. Invalid-input fail-safe and startup
sources do not establish live thermistor correspondence.

The retained PID05 decoder specifies `A-40 degC`. Therefore `T>=10` implies
`A-40=T-50`. Equality of a coordinate's `x-50` with a decoded PID05 value
additionally requires `x=T` and corresponding samples. A simultaneous read
alone does not establish those conditions.

Hysteresis changes P's value, not its count unit. Snapshot refresh changes
the sample, not the nominal grid. Neither permits unconditional equality
with a live PID. Service override and fail-safe values do not independently
establish measured physical temperature.

## Executable boundary

The gate executes stock instructions in place through the existing `PathSh2`
interpreter. It uses no replacement opcode handlers, stubs, relocations,
calculated producer-output seeds, or silently skipped unsupported instructions.
Unmapped memory reads and unsupported instructions fail closed.

The independently retained spans cover every executed instruction, delay slot,
pool load, transfer-table read, stock selection flag, byte copy, caller
argument, selected PID branch, and response helper. They include the actual
1ME3B `00062ffe` argument-offset load, the coordinate load at `00063000`,
and the JK78C selected PID branch/helper.
Full-image hashing does not replace explicit byte and flow expectations.

Each independent execution window declares incoming RAM/register/stack state
and permitted writes. W/q, old, service state/override, unrelated copy/stack
lanes, parsed PID selector, response cursor, and return context are inputs.
T, A, P, and x are executed results. Isolated clipping-arithmetic cases declare
T=9/10/11 as independent slice operands; they do not claim those are all actual
stock lookup outputs.

The scoped caller checks use explicit net frame displacements: JK78C `0x70`,
1ND `0x60`, and 1ME3B `0x60`. Independently bound prologue bytes establish
static frame geometry; their FPU instructions are not executed. The executed
integer windows establish byte-width loads, argument placement, unsigned
extension, axis operands, and relevant call/delay-slot behavior. They stop
before excluded FPU consumers or complete cold lookups.

The gate checks all input byte values, source-word truncation boundaries, the
transfer kernel's upper endpoint at 248, the three normal publication arms
and equality thresholds, service override, snapshot copy, and scoped caller
operands. Observed PC/load/store paths, addresses, widths, values, and guards
are checked against independent expectations. Stock axis points bind the
nominal grid and its inverse.

Binding mutants reject each retained span. Separately executed in-memory
mutants test meaningful source/destination, width, signedness, shift,
subtraction/clipping, publication, copy, caller, PID, and delay-slot changes
without treating snapshot rejection as execution. Static-only excluded frame
bindings require binding rejection, not execution of their FPU instructions.
Tests do not produce patch images.

## Counterexamples

- q=240/241 is accepted by the normal source-validity branch but produces
  T=8/7 and A=0. PID decodes -40, while T-50 gives -42/-43.
- q=220 produces T=42. old=42/43 takes the retained-middle arm; old=44
  executes the fall-limit ADD even though its output equals old. Visited PC
  checks distinguish these cases. old=90 produces P=x=44, whose nominal -6
  differs from the same-source decoded PID -8.
- A snapshot produced with q=200 retains x=57 while a later PID update with
  q=220 gives A=32. The decoded values 7 and -8 differ. This is an
  independent-window counterexample, not a scheduler-age bound.
- W=1023/1024 yields q=255/0. It is truncation/wrap, not source-word
  saturation or proof of the physical ADC input range.
