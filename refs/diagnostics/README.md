# Diagnostic and CAN knowledge corpus

This directory contains reproducible, source-preserving projections of the
diagnostic and CAN evidence used by the project. Memgraph is the integration and
query layer. CSV and JSONL files are tracked inputs and portable exports, not a
second database.

The v1 completeness claim is scoped corpus completeness:

- all 29 retained PDFs in the local 2007 Infiniti G35 Sedan ESM and all 31
  retained PDFs in the local 2013 Infiniti G Sedan ESM are inventoried;
- every retained diagnostic document produces structured evidence, except the
  directly cited electrical, starting-system, and engine-mechanical references;
- every configured DTC descriptor in JK00D, JK03A, and JK08A is preserved;
- every row in each pinned community source is either projected or retained in
  a source fragment;
- missing semantics, target applicability, physical CAN identifiers, and
  byte/bit layouts remain explicit unknowns.

The corpus is not a complete physical description of every V36 CAN bus. Factory
CAN signal matrices identify transmitters and receivers but generally do not
provide arbitration IDs or payload layouts. Community definitions are not
treated as JK08A hardware truth until a bench or vehicle observation confirms
them.

does not filter technical ingestion. Applicability and verification status do.

## Provenance contract

Every derived claim has a stable `dataset_id` and `source_fragment_id`.

- `documents.csv` identifies the exact PDF, ROM image, repository file, URL,
  revision, and SHA-256 where available.
- `fragments.jsonl` preserves the source page, line range, JSON pointer, or ROM
  byte range and the source text or record.
- Structured CSV rows refer back to one fragment.
- Conflicting names, units, scales, and formulas remain separate rows.
- Duplicate ROM descriptors for the same public DTC remain separate by ROM
  index and address.

`Active Test`, Work Support, initialization, clear-DTC, and other command
definitions have `executable=false`. The corpus and query CLI contain no command
transmission implementation.

Fixed-width ESM tables preserve their available semantics as structured claim
properties. Data Monitor and operation definitions retain descriptions,
conditions, reference values, and usage where present in the source. Display
content, operating conditions, reference values, operation selections, and
check items remain separate fields. Missing fields remain empty rather than
being inferred. DTC procedure pages are linked separately from index
definitions; table-of-contents references are not treated as procedure pages.
Continuation tables at the start of a page are associated with their preceding
diagnostic mode even when another mode begins later on the same page. Work
Support service-setting rows retain only the mode selections that belong to the
same service item.
Page ownership follows the first page heading or the top
`DIAGNOSIS SYSTEM (...)` heading, so incidental references to another ECU do not
change attribution. Both code-first and title-first DTC indexes are supported.
Wrapped SRS titles and bracket-qualified titles are reconstructed without
absorbing adjacent repair-order text.

The read-only query layer searches names and structured semantic fields without
merging source claims. Multiword searches require an adjacent phrase, with
space, hyphen, and slash treated as accepted term separators. Consult-specific
aliases resolve common abbreviated names. Results rank exact factory evidence
before homologous community and generic-family evidence while preserving
applicability and verification status on every claim.

## Generated files

The tracked projections are regenerated by the scripts under
`tools/diagnostics/`. The scoped ESM source packs are stored under
`refs/nissan-esm-2007-g35-sedan/` and `refs/nissan-esm-2013-g37-sedan/`; each
directory documents its own retention boundary and recovery path.
`NissanDatatable.pdf` remains in the local document archive. Pinned Git sources
are supplied as local checkouts; each importer rejects a different revision or
locally modified input files.

```bash
uv run python tools/diagnostics/extract_rom_dtc.py

uv run python tools/diagnostics/extract_esm.py \
  refs/nissan-esm-2007-g35-sedan

uv run python tools/diagnostics/extract_esm.py \
  refs/nissan-esm-2013-g37-sedan \
  --pack refs/diagnostics/nissan-esm-2013-g37-sedan/source_pack.toml

uv run python tools/diagnostics/import_370z_logger.py /path/to/370Z-CAN-Logger
uv run python tools/diagnostics/import_obd2tools.py /path/to/obd2tools
uv run python tools/diagnostics/import_ecudocs.py /path/to/ecudocs.com

uv run python tools/diagnostics/import_nissan_datatable.py \
  "/path/to/NissanDatatable.pdf"
```

Run the complete offline contract check before touching Memgraph:

```bash
uv run python tools/memgraph/ingest_diagnostics.py --dry-run
uv run pytest -q tools/diagnostics/tests
```

The diagnostic graph model and query commands are documented in
`tools/diagnostics/README.md`.
